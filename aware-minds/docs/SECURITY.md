# Security status: local development only

Passwords use salted PBKDF2-HMAC-SHA256. Sessions are random tokens stored as hashes and sent as HttpOnly, SameSite=Lax cookies; `Secure` applies in production mode. Cookie-authenticated mutations reject explicitly cross-site Origin/Fetch requests. Login limits each email to eight failures in a 15-minute window, then returns 429. App keys are random, hashed, scoped, revocable and shown once; account export omits keys/sessions/hashes. Owner and app conditions guard conversation, memory, document, project and integration queries. Admin routes check roles; a super-admin cannot be disabled by another admin.

This is **not** sufficient for public deployment. Missing: complete CSRF token strategy, global/IP throttling, hardened registration, extractor sandbox/antivirus for PDF/DOCX, abuse monitoring, TLS/reverse-proxy deployment review, delegated external end-user identities and penetration test. Filenames are normalized; maximum upload size is 5 MB; PDFs/DOCX need matching signatures and DOCX has extracted-size/member limits. Malicious instructions in documents/memories are labelled untrusted, but LLM prompt injection cannot be fully ruled out. Never feed model output into shell/SQL; no model tools or MCP are enabled. Logs include request ID/method/path/status/duration but not request bodies, tokens or private documents.
